# 重新编译说明 —— actions.dll（rime-actions 上屏动作）

> 项目：rime-actions（上屏动作）

**一句话**：只有"小狼毫换了不兼容的 Lua / 换了 CPU 架构 / 要改 C 代码"才需要重编；
改触发键、撤回次数、单次删字上限、dll 目录、**快捷触发码表（`actions/shortcuts`）、符号集
（`actions/symbols`）、组合键（`actions/hotkey`）都只需要改配置**（见 `使用说明.md` 第五、六节）。
本目录这一版 dll 已经带 `press_keys`（发任意组合键用）、**v7 的扫描码注入**（修 `ss;`/`ww;`
"只跳光标、选不中"）、**v8 的 `open_url`**（`f;` 用浏览器搜最后一次上屏）、**v9 的可配按键间隔**
（`actions/key_gap_ms`，`press_keys` 多了第二个参数）和 **v10 的 AI 能力**
（`http_request` / `send_text` / `nudge` / `clipboard_get`，`@ai` 模式用），所以四种触发方式
都不用再编。

## 一、先判断：要不要重编

| 情况 | 要不要重编 | 怎么做 |
| --- | --- | --- |
| 只改触发键 / 连续撤回次数 / 单次删字上限 / dll 目录 / 快捷键表 / 符号集 | **不用** | 改配置项 `actions/*`，重新部署 |
| 小狼毫升级，但仍是 x64 且内嵌 Lua 5.4 | **通常不用** | 跑自检：`python smoke_backspace.py "<新的 rime.dll 路径>"`，看到 `CHECKS: 423 asserted, ALL PASS` 就是兼容（AI 另跑 `python probe_ai_dll.py`） |
| 小狼毫内嵌 Lua 换成 5.5 / 5.3 / LuaJIT | 要 | 换对应版本的头文件再编（`luaL_checkversion_` 会拒绝不匹配的模块） |
| 换成 ARM64 版小狼毫 | 要 | 用 ARM64 工具链重新编 |
| 要改 C 的行为（例：单次删字上限想超过 10000、想让 `press_keys` 支持新键名、想放宽 `MAX_KEY_GAP_MS 500` 的上限） | 要 | 改 `actions.c` 后重编 |

自检脚本（离线校验，不注入任何按键）：
`C:\Users\Administrator\Desktop\Ai_Work\DSH_harness\smoke_backspace.py`

**运行位置**：没讲究，脚本自己算仓库根；只要别把当前目录设成
`backspace-build`。因为 Lua 默认的 cpath 里有 `.\?.dll` 这一条，若 cwd 正好是
`backspace-build`，它会把那里的正式 `actions.dll` 当成模块加载进来，导致场景 E
（故意写坏 `dll_dir`）判定被跳过、出现假的 `E_* FAILED`。

## 三、一键重编

1. 打开 `build.cmd`，确认目标目录：
   `if "%WEASEL_DIR%"=="" set "WEASEL_DIR=C:\Program Files\Rime\weasel-0.17.4"`
   换版本就改这一行（也可以临时用环境变量 `WEASEL_DIR` / `MINGW_BIN` 覆盖）。
2. 双击 `build.cmd`（或在 cmd 里执行）。
3. 看到 `[2/2] done` 和输出大小 / SHA256 就成功了。
4. 期望产物：`actions.dll`，**93209 B**，
   sha256 `c2f6aeebc28408a0a902972287e848bf25b58869b437928f35c5a99b15ca16cb`。
   编译选项带 `-Wl,--no-insert-timestamp`，同样的源码每次编译**逐字节一致**。
   （注意：产物文件名也要一样。DLL 内部记着自己的名字，输出成别的名字哈希就会变。）

## 四、手工命令（与 `build.cmd` 等价）

```bat
set "PATH=C:\msys64\mingw64\bin;%PATH%"
gcc -shared -fPIC -o actions.dll actions.c -Iinclude -L"C:\Program Files\Rime\weasel-0.17.4" -luser32 -lshell32 -lwinhttp -lrime -O2 -Wl,--no-insert-timestamp
```

| 参数 | 作用 |
| --- | --- |
| `-shared -fPIC` | 生成 DLL |
| `actions.c` | **只编译这一个文件**，不涉及 `keycodes.c` 等其它源文件 |
| `-Iinclude` | Lua 5.4 头文件目录 |
| `-L"...\weasel-0.17.4"` + `-lrime` | 提供 `luaL_checkversion_` / `luaL_checklstring` / `luaL_optinteger` / `luaL_optlstring` / `luaL_setfuncs` / `lua_createtable` / `lua_pushinteger` / `lua_pushlstring` / `lua_pushnil` / `lua_pushstring` |
| `-luser32` | 提供 `SendInput`、`MapVirtualKeyW`（v7 起取扫描码用）、剪贴板三件（v10 起 `clipboard_get` 用） |
| `-lshell32` | 提供 `ShellExecuteW`（v8 起 `@search` 打开网址用；**漏了会报 `undefined reference to 'ShellExecuteW'`**） |
| `-lwinhttp` | 提供 `WinHttp*`（v10 起 `@ai` 联网用；**漏了会报 `undefined reference to 'WinHttpOpen'`** 等 12 个符号） |
| `-O2` | 优化 |
| `-Wl,--no-insert-timestamp` | 时间戳置 0，可复现构建 |

不想直接链 `rime.dll` 时，可以先生成导入库再用：

```bat
dlltool -d lib\rime-lua.def -l lib\librime-lua.a -D rime.dll
gcc -shared -fPIC -o actions.dll actions.c -Iinclude lib\librime-lua.a -luser32 -lshell32 -lwinhttp -O2 -Wl,--no-insert-timestamp
```

（`lib\rime-lua.def` 只列了最早的 5 个符号；走这条路要先把 v10 另外用到的
`luaL_checklstring` / `luaL_optlstring` / `lua_pushlstring` / `lua_pushnil` / `lua_pushstring`
补进 def，否则链接会报未定义。按 `build.cmd` 直接链 `rime.dll` 是 93209 B。）

## 五、核对产物

```powershell
objdump -p .\actions.dll | Select-String '+base\[|DLL Name|luaL_|lua_'
objdump -d .\actions.dll | Select-String 2710      # cmp $0x2710,%rax  → 上限 10000 已编进去
```

期望：导出**只有** `luaopen_actions`。模块表里现在有十三个函数（`objdump -p` 看不到它们）：

| 函数 | 起 | 作用 |
| --- | --- | --- |
| `press_backspace(n)` | v3 | 退格 n 次，返 1 接受 / 0 忙或太近 |
| `press_keys(spec[, gap])` | v6 | 按组合键序列，gap 默认 30、上限 500 |
| `open_url(url)` | v8 | 用默认程序打开网址，1 安排 / 2 忙 / 0 非法 |
| `http_request` / `http_state` / `http_result` / `http_cancel` | v10 | 后台请求的四件套（序号 / 状态 / 取回 / 取消） |
| `clipboard_get()` | v10 | 同步读剪贴板（保留的老接口） |
| `clipboard_request` / `clipboard_take` | v11 | 后台读剪贴板的两步接口 |
| `send_text(utf8)` | v10 | 把文字逐个字符打出去，1 安排 / 2 上一段还在打 |
| `press_backspace_then_text(n, text)` | v12 | 先删 n 个退格、再打这段文字，1 / 2 / 0 |
| `nudge(delay[, vk])` | v10 | 延时后敲一下空键（默认 F24）把输入法叫醒 |

从 `rime.dll` 导入上面那 10 个符号；
`USER32.dll` 导入 `SendInput` 与 `MapVirtualKeyW`（v7 起用后者取扫描码）；`SHELL32.dll` 导入
`ShellExecuteW`（v8 起，`f;` 用）；`WINHTTP.dll` 导入 12 个 `WinHttp*`（v10 起，`@ai` 用）；
`KERNEL32.dll`
除 `Sleep` 等外还会多出 `CreateThread` / `CloseHandle` / `GetTickCount64`（异步注入用的
后台线程与真时钟）、`MultiByteToWideChar` / `WideCharToMultiByte` / `GlobalLock` / `GlobalUnlock`
（v10 的 HTTP 与剪贴板）；没有 `libgcc` / `libwinpthread` 依赖。

**测试版 dll（dry-run）**：`C:\Users\Administrator\Desktop\Ai_Work\DSH_harness\smoke_backspace.py`
会自己用 `-DACTIONS_DRY_RUN` 编一个**只记事件、不真的发键、不联网**的临时 dll（v10 起是
93910 B，多了 `-lshell32` 与 `-lwinhttp`），再断言按键序列（`ctrl+z` → `1Ds,2Cs,2Cs-up,1Ds-up`，
`s` = 扫描码写法、`x` = 扩展键）、`open_url` 的 URL、`send_text` 的 UNICODE 事件、`nudge` 的延时。
正式 dll 里没有 `_dry_run_*` 钩子，可用
`C:\Users\Administrator\Desktop\Ai_Work\DSH_harness\probe_prod_dll.py`
核对（它只发"一定非法"的 spec/地址，不会真的按键或开浏览器）；`..\probe_ai_dll.py` 验 AI 那 7 个
函数（HTTP 只打它自己起的 `127.0.0.1` 服务、`send_text` 只测空串与超长、`nudge` 只敲一次空键、
剪贴板只读）；要连真实注入一起验，用
`..\probe_scan_e2e.py`（自己开窗口、自己抢前台、只往那个窗口发键）和
`..\probe_open_url_e2e.py`（起一个本地 HTTP 服务当靶子，看浏览器有没有真的访问过去）。

> **运行位置有讲究**：Lua 默认 `package.cpath` 里有 `.\?.dll`，在**放着正式 `actions.dll`
> 的目录里**跑 `smoke_backspace.py`，它会优先加载那个真的 dll，导致"模块加载失败"那条用例被跳过、
> 出现假的 `E_* FAILED`。要么在上层目录跑（`smoke_backspace.py` 会自己算仓库根），要么把
> `SMOKE_SKIP_F=1` 设上。

## 七、常见错误对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `gcc` 只输出 `Error 1`，什么错都不打印 | `C:\msys64\mingw64\bin` 不在 `PATH`，`cc1.exe` 静默退出（`0xC0000135`） | 用 `build.cmd`（它自己设 PATH） |
| `as.exe` 报 `0xC0000139` STATUS_ENTRYPOINT_NOT_FOUND | `System32` 里旧的 `zlib1.dll` 抢先命中 | 已修：把 `C:\msys64\mingw64\bin\zlib1.dll` 复制到 `C:\msys64\mingw64\x86_64-w64-mingw32\bin\` |
| `undefined reference to 'lua_pushinteger'`（或另 4 个） | 少了 `-L<rime.dll 目录> -lrime` | 补上，这 5 个符号只能由 `rime.dll` 提供 |
| 日志 `module 'actions' not found` | 文件名不是 `actions.dll`，或不在 `actions/dll_dir` 指的位置 | 改名 / 改配置 |
| 日志 `failed to load actions: ... version mismatch` | 小狼毫内嵌 Lua 大版本变了 | 换对应头文件重编 |
| 覆盖 dll 失败（文件被占用） | `WeaselServer.exe` 还开着 | 先停服务再覆盖 |
| 连着触发几次后小狼毫崩溃退出（事件日志里错误模块是 `rime.dll`、异常码 `0xc0000005`） | 旧版 dll 是在回调里同步注入按键（引擎被重入） | 用本目录 v3 的 dll（异步注入），换完重新部署 |
| 触发后删多 / 删少 | 智能退格、emoji 代理对、含换行等 | 见 `使用说明.md` 第八节 |
| 触发完全没反应 | 参数没生效 / 触发码字符不在 `alphabet` / 被键绑定占用 | 看日志里的生效值 + `使用说明.md` 第四节 |
| 目标程序以管理员身份运行 | `SendInput` 受 UIPI 限制被拦 | 与 dll 无关，绕不过 |
| 日志 `press_keys is unavailable` | 换回了旧 dll（没有 `press_keys`），但配置里写了 `actions/shortcuts` | 换本目录这版 dll（93209 B） |

| 某个程序里快捷键"只走了第一步"，或者 `ss;`/`ww;` 像 Shift 没按住 | 按键间隔对那个程序来说太快 | 把 `"actions/key_gap_ms"` 调大（100~200，最多 500），不用重编 |
| 日志 `ai disabled - dll 里没有 http_request` / 打 `ai;` 没进 AI 模式 | dll 不是 v10（没有 `http_request`/`send_text`/`nudge`），或 `actions/ai/enabled` 不是 `true` | 两个文件都换成本目录这版；配置里加 `"actions/ai/enabled": true` |
| 日志 `ai: request not sent` / `HTTP 401` | 接口地址/模型名/密钥不对，或该接口不认 `thinking` 字段 | 对照 `使用说明.md` 第五节的 AI 配置表逐项核对 |
| 日志 `ai: previous request still running, not sending again` | 上一次请求还没回来就又按了发送键 | 等它回来（或 Esc 取消）再发 |
| `undefined reference to 'WinHttpOpen'` 之类 | 少了 `-lwinhttp` | 补上（`build.cmd` 已含） |
| 日志 `actions.open_url is unavailable` / 打 `f;` 不开浏览器 | dll 不是含 `open_url` 的版本（v8 起才有）；或 `ShellExecuteW` 被安全软件拦了 | 换本目录这版 dll（93209 B）；被拦就换别的打开方式 |
| 打了 `z;` 之类的触发码完全没反应 | `actions/shortcuts` 没配 / 触发码重复被停用 / 按键序列写错 / 触发码字符不在 `alphabet` | 看日志里的 `shortcuts=` 与 `disabled:` 那几行；见 `使用说明.md` 第六节 |
| `f;` 搜到的不是想要的词 | 搜索词取的是"最后一次上屏的原文"，之后删过/动过光标就对不上 | 看日志 `search … -> …`；见 `使用说明.md` 第八节第 12 条 |
| 快捷键发出去了但目标程序没反应 | 目标程序没绑这个键 / 窗口是管理员权限（UIPI）/ 被别的软件占用 | 与 dll 无关，换键或换程序 |
| 想看日志 | Win 高版本小狼毫日志在 `%TEMP%\Rime\` | 打开最新日志搜 `actions.lua` |

## 八、改行为改哪里

- **配置项（推荐，不用重编）**：`actions/trigger`、`actions/hotkey`、`actions/shortcuts`、
  `actions/search_url`、`actions/symbols`、`actions/dll_dir`、`actions/stack_size`、
  `actions/max_backspaces`、`actions/debounce_ms`、`actions/key_gap_ms`，以及 `actions/ai/*` 那 30 项
  （见 `使用说明.md` 第五节 AI 配置表）；默认值在 `actions.lua:66`（`DEFAULTS`），
  安全上限在 `actions.lua:129`（`LIMITS`），关闭文本触发的 `TRIGGER_OFF` 在 `actions.lua:150` 附近，
  26 项默认快捷键表 `DEFAULT_SHORTCUTS` 在 `actions.lua:155`，
  读取与回落逻辑在 `actions.lua:2372` 的 `init(env)`（AI 那组在 `actions.lua:2247` 的 `init_ai()`），
  触发判定在 `actions.lua:2500` 的 `func(key, env)`，
  快捷键表解析在 `actions.lua:413` 的 `parse_shortcuts()`，搜索在 `actions.lua:812` 的 `fire_search()`，
  AI 发送/取回在 `actions.lua:1215` / `actions.lua:1552`。
  **AI 拼音候选（v14，纯 Lua）**：提示词 `AI_PINYIN_PROMPT` 在 `actions.lua:1807`，结果校验 `ai_pinyin_accept` 在 `:1889`，发送 `ai_pinyin_send` 在 `:1948`，轮询 `ai_pinyin_tick` 在 `:2011`，按键处理 `ai_pinyin_handle_key` 在 `:2119`，配置读取 `init_ai_pinyin` 在 `:2164`；拼音捕获在 `ai_pinyin_capture.lua`，候选插入在 `ai_pinyin_insert.lua`。这三处都是 Lua，改完不用重编 dll。
- **接线方式**（改方案，不用重编）：`actions.lua` 是 **processor** 组件，必须挂在
  `engine/processors` 里，推荐放最前（`@before 0`）：
  `engine/processors/@before 0: lua_processor@*wanxiang.ziji.actions`。
  挂在 `engine/translators` 里会照旧触发小狼毫崩溃（`0xc0000005`）。
- **只有改代码才生效的**：`actions.c:79` 的 `#define MAX_BACKSPACES 10000`（dll 侧防呆上限），
  `actions.c:82-86` 的异步注入参数：`FIRE_DELAY_MS 80`（延迟多久开始发）、
  `BATCH_SIZE 8`（每批发几个）、`BATCH_GAP_MS 5`（批间隔）、`MIN_INTERVAL_MS 150`
  （多久内的重复触发直接丢弃），以及 `press_keys` 的三个上限：`STEP_GAP_MS 30`（`actions.c:88`，默认按键间隔）/`MAX_KEY_GAP_MS 500`
  （`actions.c:89`，多步序列的步间隔）、`MAX_SPEC_LEN 255`（`:91`）、
  `MAX_CHORD_EVENTS 12`（`:92`，一步最多几个键事件）；键名白名单与解析在
  `actions.c:4-62` 的注释与 `:294`/`:400` 的解析函数里（加键名要动这里）。
  **v7 另加了两件事**：`fill_key()`（按键事件带扫描码 + `KEYEVENTF_SCANCODE`，`wVk` 置 0，
  取不到扫描码才退回只填 `wVk`；在 `build_chord()` 之前）和 `vk_is_extended()`（扩展键清单：
  `PRIOR/NEXT/END/HOME/LEFT/UP/RIGHT/DOWN/INSERT/DELETE`、`LWIN/RWIN/APPS`、`DIVIDE`、
  `RCONTROL`、`RMENU`）—— 没有这条清单，`Home`/方向键会被当成小键盘数字发出去。
  **退格那条路（`inject_backspaces()`）没动**，仍是只填 `wVk` 的老写法。
  **v9 加了三样**：`send_events_spaced(events, total, gap)`（`gap > 0` 时 `SendInput(1, ...)` 逐个事件发、相邻事件 `Sleep(gap)`；`gap <= 0` 退回 `send_batch`）、`press_keys` 的可选第二参数（`luaL_optinteger(L, 2, STEP_GAP_MS)`，负数当 0、超过 `MAX_KEY_GAP_MS` 截到 500）与 dry-run 的 `_dry_run_gap`（返回最后一次解析出的间隔，供探针断言）。**v8 另外有三样**：`open_url_now()`（`MultiByteToWideChar(CP_UTF8)` + `ShellExecuteW`，
  在后台线程里调）、`url_is_valid()`（只放行 `http://`/`https://`，拒绝 `<=0x20`、`0x7F`、
  `"` `<` `>` `|`）、`l_open_url()`（异步槽位 `g_pending_kind = 3`，`g_pending_url[MAX_URL_LEN+1]`
  用 `MAX_URL_LEN 2048`；返回值 1 已排队 / 2 被忽略 / 0 参数非法）；链接时要加 `-lshell32`。
  网址里的中文由 Lua 侧先 percent-encode，C 侧只负责原样打开。
  **v10 加了 AI 那一片（都在 `actions.c` 里，改要重编）**：`http_thread_main()`（WinHTTP
  后台线程：`WinHttpOpen` → `WinHttpCrackUrl` → `WinHttpConnect` → `WinHttpOpenRequest` →
  `WinHttpSendRequest` → `WinHttpReceiveResponse`，超时用 `WinHttpSetTimeouts`，结果存
  `g_http_body`）、`l_http_request` / `l_http_state` / `l_http_result` / `l_http_cancel`
