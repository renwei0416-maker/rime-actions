# 重新编译说明 —— sendKeyCode.dll（Backspace 版）

**一句话**：只有"小狼毫换了不兼容的 Lua / 换了 CPU 架构 / 要改 C 代码"才需要重编；
改触发键、撤回次数、单次删字上限、dll 目录、**快捷触发码表（`revert/shortcuts`）、符号集
（`revert/symbols`）、组合键（`revert/hotkey`）都只需要改配置**（见 `使用说明.md` 第五、六节）。
本目录这一版 dll 已经带 `press_keys`（发任意组合键用）、**v7 的扫描码注入**（修 `ss;`/`ww;`
"只跳光标、选不中"）、**v8 的 `open_url`**（`f;` 用浏览器搜最后一次上屏）和 **v9 的可配按键间隔**
（`revert/key_gap_ms`，`press_keys` 多了第二个参数），所以三种触发方式
都不用再编。

---

## 一、先判断：要不要重编

| 情况 | 要不要重编 | 怎么做 |
| --- | --- | --- |
| 只改触发键 / 连续撤回次数 / 单次删字上限 / dll 目录 / 快捷键表 / 符号集 | **不用** | 改配置项 `revert/*`，重新部署 |
| 小狼毫升级，但仍是 x64 且内嵌 Lua 5.4 | **通常不用** | 跑自检：`python smoke_backspace.py "<新的 rime.dll 路径>"`，看到 `CHECKS: 182 asserted, ALL PASS` 就是兼容 |
| 小狼毫内嵌 Lua 换成 5.5 / 5.3 / LuaJIT | 要 | 换对应版本的头文件再编（`luaL_checkversion_` 会拒绝不匹配的模块） |
| 换成 ARM64 版小狼毫 | 要 | 用 ARM64 工具链重新编 |
| 要改 C 的行为（例：单次删字上限想超过 10000、想让 `press_keys` 支持新键名、想放宽 `MAX_KEY_GAP_MS 500` 的上限） | 要 | 改 `sendKeyCode.c` 后重编 |

自检脚本（离线校验，不注入任何按键）：
`tests\smoke_backspace.py`

**运行位置有讲究**：要在上层目录（`...\DSH_harness`）跑，或者至少别把当前目录设成
`backspace-build`。因为 Lua 默认的 cpath 里有 `.\?.dll` 这一条，若 cwd 正好是
`backspace-build`，它会把那里的正式 `sendKeyCode.dll` 当成模块加载进来，导致场景 E
（故意写坏 `dll_dir`）判定被跳过、出现假的 `E_* FAILED`。

## 二、准备清单

**必须有**：

| 需要什么 | 本机位置 / 说明 |
| --- | --- |
| gcc（MinGW-w64 **x64**） | `C:\msys64\mingw64\bin\gcc.exe`（16.2.0） |
| binutils（核对产物用） | `C:\msys64\mingw64\bin\objdump.exe`（2.47-4） |
| 目标小狼毫的 `rime.dll`（x64） | `C:\Program Files\Rime\weasel-0.17.4\rime.dll` |
| Lua 5.4 头文件 | 本目录 `include\`：`lua.h` / `luaconf.h` / `lauxlib.h`（Lua 5.4.0，`LUA_VERSION_NUM 504`） |

**不需要**：

- `make`（`build.cmd` 里就是一条 `gcc` 命令）
- MSVC / Visual Studio / Windows SDK
- 独立的 Lua 开发包或 `lua.exe`：`rime.dll` 自己内嵌 Lua 5.4，链接时直接从它取符号

## 三、一键重编

1. 打开 `build.cmd`，确认目标目录：
   `if "%WEASEL_DIR%"=="" set "WEASEL_DIR=C:\Program Files\Rime\weasel-0.17.4"`
   换版本就改这一行（也可以临时用环境变量 `WEASEL_DIR` / `MINGW_BIN` 覆盖）。
2. 双击 `build.cmd`（或在 cmd 里执行）。
3. 看到 `[2/2] done` 和输出大小 / SHA256 就成功了。
4. 期望产物：`sendKeyCode.dll`，**36734 B**，
   sha256 `c1d95fc430dc24abd879777c73430ffad0a13815c9333f33dcf0f558e01c6b2b`。
   编译选项带 `-Wl,--no-insert-timestamp`，同样的源码每次编译**逐字节一致**。
   （注意：产物文件名也要一样。DLL 内部记着自己的名字，输出成别的名字哈希就会变。）

## 四、手工命令（与 `build.cmd` 等价）

```bat
set "PATH=C:\msys64\mingw64\bin;%PATH%"
gcc -shared -fPIC -o sendKeyCode.dll sendKeyCode.c -Iinclude -L"C:\Program Files\Rime\weasel-0.17.4" -luser32 -lshell32 -lrime -O2 -Wl,--no-insert-timestamp
```

| 参数 | 作用 |
| --- | --- |
| `-shared -fPIC` | 生成 DLL |
| `sendKeyCode.c` | **只编译这一个文件**，不涉及 `keycodes.c` 等其它源文件 |
| `-Iinclude` | Lua 5.4 头文件目录 |
| `-L"...\weasel-0.17.4"` + `-lrime` | 提供 `luaL_checkversion_` / `luaL_checklstring` / `luaL_optinteger` / `luaL_setfuncs` / `lua_createtable` / `lua_pushinteger` |
| `-luser32` | 提供 `SendInput` 与 `MapVirtualKeyW`（v7 起取扫描码用） |
| `-lshell32` | 提供 `ShellExecuteW`（v8 起 `@search` 打开网址用；**漏了会报 `undefined reference to 'ShellExecuteW'`**） |
| `-O2` | 优化 |
| `-Wl,--no-insert-timestamp` | 时间戳置 0，可复现构建 |

不想直接链 `rime.dll` 时，可以先生成导入库再用：

```bat
dlltool -d lib\rime-lua.def -l lib\librime-lua.a -D rime.dll
gcc -shared -fPIC -o sendKeyCode.dll sendKeyCode.c -Iinclude lib\librime-lua.a -luser32 -lshell32 -O2 -Wl,--no-insert-timestamp
```

（结果等价；那次编出来是 26816 B，现在这版按 `build.cmd` 编是 36734 B。）

## 五、核对产物

```powershell
objdump -p .\sendKeyCode.dll | Select-String '+base\[|DLL Name|luaL_|lua_'
objdump -d .\sendKeyCode.dll | Select-String 2710      # cmp $0x2710,%rax  → 上限 10000 已编进去
```

期望：导出**只有** `luaopen_sendKeyCode`（模块表里是 `press_backspace` / `press_keys` / `open_url`
三个函数，`objdump -p` 看不到它们）；从 `rime.dll` 导入上面那 6 个符号；
`USER32.dll` 导入 `SendInput` 与 `MapVirtualKeyW`（v7 起用后者取扫描码）；`SHELL32.dll` 导入
`ShellExecuteW`（v8 起，`f;` 用）；`KERNEL32.dll`
除 `Sleep` 等外还会多出 `CreateThread` / `CloseHandle` / `GetTickCount64`（异步注入用的
后台线程与真时钟）；没有 `libgcc` / `libwinpthread` 依赖。

**测试版 dll（dry-run）**：`tests\smoke_backspace.py`
会自己用 `-DSENDKEYCODE_DRY_RUN` 编一个**只记事件、不真的发键**的临时 dll（v9 起是 74733 B，
多了 `-lshell32`），再断言按键序列（`ctrl+z` → `1Ds,2Cs,2Cs-up,1Ds-up`，`s` = 扫描码写法、
`x` = 扩展键）与 `open_url` 的 URL。正式 dll 里没有 `_dry_run_*` 钩子，可用
`tests\probe_prod_dll.py`
核对（它只发"一定非法"的 spec/地址，不会真的按键或开浏览器）；要连真实注入一起验，用
`..\probe_scan_e2e.py`（自己开窗口、自己抢前台、只往那个窗口发键）和
`..\probe_open_url_e2e.py`（起一个本地 HTTP 服务当靶子，看浏览器有没有真的访问过去）。

## 六、部署

```powershell
# 1) 先停服务：任务栏小狼毫右键 → 停止服务（或结束 WeaselServer.exe）
# 2) 备份并覆盖（默认目录；别人机器上也是这个布局）
$dst = "$env:APPDATA\Rime\lua\wanxiang\ziji\sendKeyCode"
Copy-Item "$dst\sendKeyCode.dll" "$dst\sendKeyCode.dll.bak" -Force
Copy-Item .\sendKeyCode.dll $dst -Force
# 3) 启动服务，右键 → 重新部署
```

参数覆盖写在 `*.custom.yaml` 的 `patch:` 里（键名与默认值见 `使用说明.md` 第五节）。

## 七、常见错误对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `gcc` 只输出 `Error 1`，什么错都不打印 | `C:\msys64\mingw64\bin` 不在 `PATH`，`cc1.exe` 静默退出（`0xC0000135`） | 用 `build.cmd`（它自己设 PATH） |
| `as.exe` 报 `0xC0000139` STATUS_ENTRYPOINT_NOT_FOUND | `System32` 里旧的 `zlib1.dll` 抢先命中 | 已修：把 `C:\msys64\mingw64\bin\zlib1.dll` 复制到 `C:\msys64\mingw64\x86_64-w64-mingw32\bin\` |
| `undefined reference to 'lua_pushinteger'`（或另 4 个） | 少了 `-L<rime.dll 目录> -lrime` | 补上，这 5 个符号只能由 `rime.dll` 提供 |
| 日志 `module 'sendKeyCode' not found` | 文件名不是 `sendKeyCode.dll`，或不在 `revert/dll_dir` 指的位置 | 改名 / 改配置 |
| 日志 `failed to load sendKeyCode: ... version mismatch` | 小狼毫内嵌 Lua 大版本变了 | 换对应头文件重编 |
| 覆盖 dll 失败（文件被占用） | `WeaselServer.exe` 还开着 | 先停服务再覆盖 |
| 连着触发几次后小狼毫崩溃退出（事件日志里错误模块是 `rime.dll`、异常码 `0xc0000005`） | 旧版 dll 是在回调里同步注入按键（引擎被重入） | 用本目录 v3 的 dll（异步注入），换完重新部署 |
| 触发后删多 / 删少 | 智能退格、emoji 代理对、含换行等 | 见 `使用说明.md` 第八节 |
| 触发完全没反应 | 参数没生效 / 触发码字符不在 `alphabet` / 被键绑定占用 | 看日志里的生效值 + `使用说明.md` 第四节 |
| 目标程序以管理员身份运行 | `SendInput` 受 UIPI 限制被拦 | 与 dll 无关，绕不过 |
| 日志 `press_keys is unavailable` | 换回了旧 dll（没有 `press_keys`），但配置里写了 `revert/shortcuts` | 换本目录这版 dll（36734 B） |
| `ss;`/`ww;` 只把光标移过去、没选中（`Shift+Home`、`Ctrl+Shift+←`） | 用的是 v6 或更早的 dll（按键事件只填了 `wVk`，被输入法的钩子把修饰键吃掉） | 换本目录 v9 的 dll（36734 B） |
| 某个程序里快捷键"只走了第一步"，或者 `ss;`/`ww;` 像 Shift 没按住 | 按键间隔对那个程序来说太快 | 把 `"revert/key_gap_ms"` 调大（100~200，最多 500），不用重编 |
| 日志 `sendKeyCode.open_url is unavailable` / 打 `f;` 不开浏览器 | dll 不是含 `open_url` 的版本（v8 起才有）；或 `ShellExecuteW` 被安全软件拦了 | 换本目录 v9 的 dll（36734 B）；被拦就换别的打开方式 |
| 打了 `z;` 之类的触发码完全没反应 | `revert/shortcuts` 没配 / 触发码重复被停用 / 按键序列写错 / 触发码字符不在 `alphabet` | 看日志里的 `shortcuts=` 与 `disabled:` 那几行；见 `使用说明.md` 第六节 |
| `f;` 搜到的不是想要的词 | 搜索词取的是"最后一次上屏的原文"，之后删过/动过光标就对不上 | 看日志 `search … -> …`；见 `使用说明.md` 第八节第 12 条 |
| 快捷键发出去了但目标程序没反应 | 目标程序没绑这个键 / 窗口是管理员权限（UIPI）/ 被别的软件占用 | 与 dll 无关，换键或换程序 |
| 想看日志 | Win 高版本小狼毫日志在 `%TEMP%\Rime\` | 打开最新日志搜 `revert.lua` |

## 八、改行为改哪里

- **配置项（推荐，不用重编）**：`revert/trigger`、`revert/hotkey`、`revert/shortcuts`、
  `revert/search_url`、`revert/symbols`、`revert/dll_dir`、`revert/stack_size`、
  `revert/max_backspaces`、`revert/debounce_ms`；默认值在 `revert.lua:61`（`DEFAULTS`），
  安全上限在 `revert.lua:75`（`LIMITS`），关闭文本触发的 `TRIGGER_OFF` 在 `revert.lua:82`，
  26 项默认快捷键表 `DEFAULT_SHORTCUTS` 在 `revert.lua:87`，
  读取与回落逻辑在 `revert.lua:647` 的 `init(env)`，触发判定在 `revert.lua:724` 的 `func(key, env)`,
  快捷键表解析在 `revert.lua:300` 的 `parse_shortcuts()`，搜索在 `revert.lua:599` 的 `fire_search()`。
- **接线方式**（改方案，不用重编）：`revert.lua` 是 **processor** 组件，必须挂在
  `engine/processors` 里，推荐放最前（`@before 0`）：
  `engine/processors/@before 0: lua_processor@*wanxiang.ziji.sendKeyCode.revert`。
  挂在 `engine/translators` 里会照旧触发小狼毫崩溃（`0xc0000005`）。
- **只有改代码才生效的**：`sendKeyCode.c:35` 的 `#define MAX_BACKSPACES 10000`（dll 侧防呆上限），
  `sendKeyCode.c:38-42` 的异步注入参数：`FIRE_DELAY_MS 80`（延迟多久开始发）、
  `BATCH_SIZE 8`（每批发几个）、`BATCH_GAP_MS 5`（批间隔）、`MIN_INTERVAL_MS 150`
  （多久内的重复触发直接丢弃），以及 `press_keys` 的三个上限：`STEP_GAP_MS 30`（默认按键间隔的下限口径）/`MAX_KEY_GAP_MS 500`
  （`sendKeyCode.c:65`，多步序列的步间隔）、`MAX_SPEC_LEN 255`（`:67`）、
  `MAX_CHORD_EVENTS 12`（`:68`，一步最多几个键事件）；键名白名单与解析在
  `sendKeyCode.c:8-20` 的注释与 `:307` 的解析函数里（加键名要动这里）。
  **v7 另加了两件事**：`fill_key()`（按键事件带扫描码 + `KEYEVENTF_SCANCODE`，`wVk` 置 0，
  取不到扫描码才退回只填 `wVk`；在 `build_chord()` 之前）和 `vk_is_extended()`（扩展键清单：
  `PRIOR/NEXT/END/HOME/LEFT/UP/RIGHT/DOWN/INSERT/DELETE`、`LWIN/RWIN/APPS`、`DIVIDE`、
  `RCONTROL`、`RMENU`）—— 没有这条清单，`Home`/方向键会被当成小键盘数字发出去。
  **退格那条路（`inject_backspaces()`）没动**，仍是只填 `wVk` 的老写法。
  **v9 加了三样**：`send_events_spaced(events, total, gap)`（`gap > 0` 时 `SendInput(1, ...)` 逐个事件发、相邻事件 `Sleep(gap)`；`gap <= 0` 退回 `send_batch`）、`press_keys` 的可选第二参数（`luaL_optinteger(L, 2, STEP_GAP_MS)`，负数当 0、超过 `MAX_KEY_GAP_MS` 截到 500）与 dry-run 的 `_dry_run_gap`（返回最后一次解析出的间隔，供探针断言）。**v8 另外有三样**：`open_url_now()`（`MultiByteToWideChar(CP_UTF8)` + `ShellExecuteW`，
  在后台线程里调）、`url_is_valid()`（只放行 `http://`/`https://`，拒绝 `<=0x20`、`0x7F`、
  `"` `<` `>` `|`）、`l_open_url()`（异步槽位 `g_pending_kind = 3`，`g_pending_url[MAX_URL_LEN+1]`
  用 `MAX_URL_LEN 2048`；返回值 1 已排队 / 2 被忽略 / 0 参数非法）；链接时要加 `-lshell32`。
  网址里的中文由 Lua 侧先 percent-encode，C 侧只负责原样打开。
