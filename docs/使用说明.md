# 上屏动作（rime-actions）使用说明

给小狼毫（Rime / Weasel）用的一个轻量扩展：让小狼毫能在系统层面执行回退、执行快捷键组合，
也能连接在线或本地的大模型。主要有四个功能模块。

### 1. 回退误上屏的内容

用默认的 **`qq/`** 或者任意自定义的编码组合，把误上屏的内容快速退回，不用连按 Backspace。
它和 `Ctrl+Z` 的逻辑不同：`Ctrl+Z` 是还原你上一次已删除的内容。

### 2. 快捷键组合

默认配置了 26 项快捷键组合，比如用 **`z;`** 执行撤销；还有删除整行、复制整行、光标移动等等。
也可以任意配置自己需要的组合，在不同编辑器里做快速操作很有帮助。

### 3. 浏览器搜索

把最后一次上屏的内容送到默认浏览器和配置好的搜索引擎里搜索。默认是 **`f;`**，
按键组合可以自己配。

### 4. AI 模式

可以任意配置。比如输入 **`ai;`** 进入 AI 模式，再用 **`//`** 把第一候选的内容发给 AI，
AI 返回的回答或补全的诗词等会直接写入光标处。上屏之后也可以直接按 **`//`**，把曾经上屏的
前一句话（不是前一次上屏）发给 AI，再把结果插入光标处；也可以配置成先删掉前一句话再插入结果。
这些按键都可以任意配置。

除 `ai;` 之外，还有 **`eng;`**、**`jp;`** 等模式，把你的输入翻译成英文、日文等。可以配置任意多个
AI 模式，用不同的按键组合配不同的提示词，让 AI 执行不同的返回。

**4.1 发送剪贴板**

进入某个 AI 模式后，用快捷组合（默认 `Ctrl+Alt+;`，可改成 `Ctrl+;g` 等）把剪贴板的文字发给 AI，
结果写回光标处。比如当前进的是 `eng;` 模式，返回的就是剪贴板内容翻译成英文的结果。

**4.2 AI 拼音候选**

用 **`aiur;`** 进入 AI 拼音模式后，AI 会结合上文分析候选框里的多个候选，把最合适的一个重排到首位；
如果现有候选都不合适，它会按拼音并结合上文生成一个最可能的结果放到第一候选，原候选依次后移。

### 小结

这个扩展不会改变你的打字方式；每个模块用哪个按键组合都可以自定义，也可以自己决定开启哪个模块。

## 一、功能

### 1. 四种触发方式

四种方式可以同时存在，各自独立。

| 方式 | 触发 | 默认 |
| --- | --- | --- |
| 文本触发码 | 中文状态下敲 `qq/` | 可用 |
| 组合键 | 按 `Ctrl+/` 之类的组合键 | 不启用 |
| 快捷触发码 | 敲 `z;`、`ss;`、`f;` 等 | 不启用 |
| AI 模式 | 敲 `ai;` 进入，打字后连按两下 `/` | 不启用 |

### 2. 动作

| 动作 | 效果 |
| --- | --- |
| 撤回上屏 | 删掉最近一次上屏的文字；再触发一次继续往前撤 |
| 按键动作 | 发送任意按键或组合键，如 `ctrl+z`、`shift+home`、`ctrl+shift+left` |
| 多步动作 | 用 `-` 或 `,` 连接多步，依次执行，如 `shift+home-ctrl+c` |
| 删到符号 | 从光标往前删到第一个符号，符号保留或一起删 |
| 删最近一笔 | 只删最近一次上屏的文字 |
| 搜索 | 用默认浏览器搜索最后一次上屏的文字 |
| AI | 把文字发给 OpenAI 格式接口，回复写到光标处 |

### 3. AI 拼音候选（筛选与纠错，默认关闭）

敲出触发码进入这个模式后，照常打拼音、选字。停手一会儿（默认 0.4 秒），脚本把当前这几个
音节和屏幕上已有的候选一起发给模型，让它做两件事：

- **筛选**：从现有候选里挑一个最合适的；
- **纠错**：都对不上时按拼音另造一个（字数必须等于音节数）。

挑中的词作为候选插到**第一位**，后面原有的候选顺序不变；只有你按数字键或空格键选中，它才上屏。
挑中的本来就是第一位时不插新候选，而是在它的注释上显示标记（默认 `AI`），提醒你"查过了、结论一致"。

拼音取自词库里的读音（`spelling_hints`），不是双拼键位；自定义短语、日期、英文这些没有拼音的
候选会被跳过，不发请求。模式用完再敲一次触发码退出（默认 `aiur;`）。

接线与配置见第三节 7。

## 二、安装

### 1. 放文件

到 Releases 下载 x64 包（`rime-actions-<版本>-x64.zip`），解压后把两个文件放进 Rime 用户目录
（小狼毫默认是 `%APPDATA%\Rime`）：

```
<Rime 用户目录>\lua\wanxiang\ziji\actions.lua
<Rime 用户目录>\lua\wanxiang\ziji\actions.dll
```

两个文件在同一目录，`actions.dll` 不能改名。

用 AI 拼音候选（第三节 7）时，再放两个文件到同一目录：

```
<Rime 用户目录>\lua\wanxiang\ziji\ai_pinyin_capture.lua
<Rime 用户目录>\lua\wanxiang\ziji\ai_pinyin_insert.lua
```

放在这个目录时不用写配置；放到别的目录时，在配置里指明位置，并把接线里的目录段一起改：

```yaml
patch:
  "actions/dll_dir": "lua/wanxiang/ziji"     # actions.dll 所在目录，相对 Rime 用户目录
```

### 2. 接线

在方案配置文件里挂上处理器。`wanxiang_pro` 方案改 `<Rime 用户目录>\wanxiang_pro.custom.yaml`，
其他方案改对应的 `*.custom.yaml`：

```yaml
patch:
  "engine/processors/@before 0": lua_processor@*wanxiang.ziji.actions
```

`@before 0` 表示排在处理器链最前面。`*wanxiang.ziji.actions` 对应
`<Rime 用户目录>\lua\wanxiang\ziji\actions.lua`，文件换目录时这一段跟着改。

### 3. 重新部署

保存后重新部署（右键托盘图标 → 重新部署）。在任意能输入的地方敲 `qq/`，最近一次上屏的文字
会被删除。

## 三、配置

配置写在 `*.custom.yaml` 的 `patch:` 下面，键名以 `actions/` 开头。全部可选，不写就是默认值。
**改完重新部署。**

下面每段都是完整的 `patch:`，可以直接复制；每行末尾是该项的说明。同一个键在一份文件里只写
一行，多行时后面的覆盖前面的。

### 0. 全部非 AI 配置项（可整段复制）

下面是本节各小节里所有非 AI 配置项的汇总，每行末尾是说明；
每项的详细规则在对应小节。AI 的配置项在 6 里单独列。

```yaml
patch:
  # ---- 触发方式：怎么叫出动作 ----
  "actions/trigger": "qq/"                  # 打完 qq 再按 / 就撤回上一次上屏；写 none / off / - 关闭
  "actions/hotkey": ""                      # 另设一个组合键做同样的撤回，如 "Control+slash"；留空不启用
  "actions/shortcuts": "@defaults"          # 快捷触发码：打出内置的 26 项做复制/撤销/选行等；不写这一行就整块不启用
  #"actions/shortcuts": "z;=ctrl+z  ss;=shift+home  ff;=@to-symbol  f;=@search"   # 只启用这几项：z; 撤销、ss; 选到行首、ff; 删到上一个符号、f; 搜索
  #"actions/shortcuts": "@defaults eq;=ctrl+end  p;=@ai:polish"                   # 26 项内置 + 自己加的：eq; 跳到文末、p; 进 AI 模式用 polish 提示词

  # ---- 删除与记录：能删多少、记多久 ----
  "actions/stack_size": 50                  # 最多记住多少笔上屏；撤完这些就撤不到更早的了
  "actions/max_backspaces": 500             # 一次动作最多删多少个字符，超过的部分不删
  "actions/debounce_ms": 200                # 连按保护：这么多毫秒内重复触发不执行，只对文本触发码生效
  "actions/key_gap_ms": 30                  # 每个按键之间（含多步动作）等多少毫秒；程序反应慢就调大
  "actions/history_ledger": true            # 读 rime 的提交历史，把万象快符打出来的符号也补进上屏记录（不补回删会少删一个）
  "actions/symbols": "，。！？；：、,.!?;:"   # 哪些字符算“符号”：删到符号、AI 去掉末尾符号都按它判断；写了就替换默认值

  # ---- 搜索与加载 ----
  "actions/search_url": "https://www.baidu.com/s?wd=%s"   # f; 搜最后一次上屏的内容时用哪个搜索引擎
  "actions/dll_dir": "lua/wanxiang/ziji"    # actions.dll 放在哪个目录（相对 Rime 用户目录）

  # ---- 日志 ----
  "actions/debug": false                    # 默认只写出错信息；排查“没反应”时改 true，才会记每次动作的细节
```

### 1. 触发方式

```yaml
patch:
  "actions/trigger": "qq/"                 # 打完 qq 再按 / 撤回上一次上屏；写 none / off / - 关闭
  "actions/hotkey": ""                     # 另设一个组合键做同样的撤回，如 "Control+slash"；留空不启用
  "actions/shortcuts": "@defaults"         # 快捷触发码：打出内置 26 项做复制/撤销/选行等；不写就不启用
```

- 文本触发码至少 2 个字符，字符要在方案的 `speller/alphabet` 里。
- 触发条件：已打出的编码恰好等于触发码的前缀，且这一次按的是最后一个字符。
  触发时最后一个字符被扩展吃掉，不上屏。
- 组合键格式为 `修饰键+键名`，修饰键可写 `Control` / `Ctrl` / `Alt` / `Shift` / `Super`，
  可叠加。键名用 Rime 键名：`slash`、`space`、`return`、`escape`、`backspace`、`left`、
  `right`、`up`、`down`、`home`、`end`、`pageup`、`pagedown`、`delete`、`tab`、字母、数字等。
- 组合键与文本触发码同开时，先判组合键，未命中再判文本触发码。输入框里有未上屏的编码时
  组合键不动作。

### 2. 快捷触发码 `actions/shortcuts`

一行里写多个，用空格分隔，每项是 `触发码=动作`。

- 不加 `@defaults`：只启用写出来的这几项。
- 加 `@defaults`：先启用内置的 26 项，再把写出来的项加进去。
- 触发码同样是"编码 + 一个字符"，至少 2 个字符，如 `z;` 是打 `z` 再按 `;`。
- 触发码重复时只保留第一项；与 `actions/trigger` 相同时不生效。两种情况都会写一条日志。
- `@defaults` 必须单独作为一个词出现；写成 `@defaultsx` 之类不会启用内置表。
- 动作里多步用 `,` 或 `-` 分隔；开头、结尾或连续出现分隔符（如 `z;=ctrl+z,,shift+home`）算写坏，
  这一项整个不生效，启动日志记 `bad key sequence disabled`。

```yaml
patch:
  "actions/shortcuts": "@defaults"                                      # 启用内置 26 项
  #"actions/shortcuts": "z;=ctrl+z  y;=ctrl+y  ss;=shift+home"           # 只启用这三项
  #"actions/shortcuts": "@defaults eq;=ctrl+end  wq;=ctrl+shift+right"   # 内置 26 项 + 两项
  #"actions/shortcuts": "hh;=shift+home-ctrl+c"                          # 多步：选到行首再复制
  #"actions/shortcuts": "@defaults p;=@ai:polish"                        # 进 AI 模式，用 polish 提示词
```

#### 内置的 26 项

| 触发码 | 动作 | 触发码 | 动作 |
| --- | --- | --- | --- |
| `z;` | `ctrl+z` 撤销 | `y;` | `ctrl+y` 重做 |
| `a;` | `ctrl+a` 全选 | `c;` | `ctrl+c` 复制 |
| `v;` | `ctrl+v` 粘贴 | `xx;` | `ctrl+x` 剪切 |
| `s;` | `up` 上移一行 | `x;` | `down` 下移一行 |
| `g;` | `end` 到行尾 | `t;` | `home` 到行首 |
| `w;` | `ctrl+shift+left` 选中前一个词 | `b;` | `ctrl+backspace` 删前一个词 |
| `r;` | `ctrl+delete` 删后一个词 | `h;` | `ctrl+home` 到文首 |
| `e;` | `ctrl+end` 到文末 | `d;` | `delete` 删除 |
| `kk;` | `ctrl+shift+k` 删整行 | `aa;` | `ctrl+a-ctrl+c` 复制全文 |
| `dd;` | `ctrl+shift+backspace` 删整行 | `ww;` | `ctrl+shift+left-ctrl+c` 复制前一个词 |
| `hh;` | `shift+home-ctrl+c` 复制整行 | `tt;` | `ctrl+shift+home-ctrl+c` 复制光标以上 |
| `gg;` | `ctrl+shift+end-ctrl+c` 复制光标以下 | `ss;` | `shift+home` 选中到行首 |
| `ff;` | `@to-symbol` 删到前一个符号 | `f;` | `@search` 搜索最后一次上屏 |

`ss;` 只选中不复制；要复制整行用 `hh;`。要连行尾换行一起选中，加一步 `shift+left`：
`sq;=shift+home,shift+left`。

#### 动作的三种写法

1. 按键或组合键：写 Rime 键名，如 `ctrl+z`、`shift+home`、`ctrl+backspace`。
   常用：字母 `a`–`z`、数字 `0`–`9`、`f1`–`f12`、`numpad0`–`numpad9`、
   `left` / `right` / `up` / `down`、`home` / `end` / `pageup` / `pagedown`、
   `insert` / `delete`、`backspace` / `tab` / `return` / `space` / `escape`、
   `slash` / `backslash` / `semicolon` 等。
2. 多步动作：`shift+home-ctrl+c` 与 `shift+home,ctrl+c` 等价。每步是"修饰键按下 → 按键
   按下 → 按键抬起 → 修饰键抬起"，相邻按键之间以及步与步之间都隔 `actions/key_gap_ms` 毫秒。
3. 内置动作，以 `@` 开头：

| 写法 | 作用 |
| --- | --- |
| `@to-symbol` | 从光标往前删到第一个符号，符号保留 |
| `@to-symbol-include` | 同上，符号一起删 |
| `@delete` | 删掉最近一次上屏的文字 |
| `@search` | 用默认浏览器搜索最后一次上屏的文字 |
| `@ai` | 进入 AI 模式，用提示词 `default` |
| `@ai:<名字>` | 进入 AI 模式，用提示词 `<名字>` |

### 3. 提示词 `actions/ai/prompts/<名字>`

AI 模式的提示词按名字存在 `actions/ai/prompts/<名字>` 下。

- 内置三份：`default`（通用）、`eng`（译成英文）、`jp`（译成日文）。
- 写同名的键覆盖内置的；写新的名字就是新增一份。
- 触发码用 `@ai:<名字>` 指向它；`@ai` 不带名字时用 `default`。
- 值是字符串，多行用 `>`（折成一行，末尾换行保留）或 `|`（保留原有换行）。

内置三份的原文：

```text
default：你是中文输入助手。如果是问题就进行精准简短的回复，如果是诗词或名句就回复原文和作者等。只输出结果正文，不要解释、不要提问、不加引号。每一次接收到的内容，单独回复不要理会之前提交的内容。

eng：Translate the user's Chinese text into natural, idiomatic English. Output only the translation, no explanations, no quotes.

jp：把用户的中文翻译成自然、地道的日语。只输出译文，不要解释，不要加引号。
```

```yaml
patch:
  # 新增一份，名字 polish
  "actions/ai/prompts/polish": >                                          # 提示词：中文润色
    你是中文润色助手。把用户给的一句话改写得更通顺，只输出改写后的句子，不要解释。
  # 新增一份，名字 note
  "actions/ai/prompts/note": >                                           # 提示词：提取要点
    把用户给的内容压缩成不超过三条要点，每条一行，只输出要点。
  # 覆盖内置的通用提示词
  "actions/ai/prompts/default": >                                        # 提示词：默认
    按用户要求处理文字，只输出结果。
  # 触发码：敲 p; 进 polish，敲 n; 进 note
  "actions/shortcuts": "@defaults p;=@ai:polish n;=@ai:note"
```

名字里不要用空格和 `/`。已经进入 AI 模式时，直接敲另一个 `@ai` 触发码即可切换提示词。

### 4. 删除与符号

```yaml
patch:
  "actions/stack_size": 50                     # 最多记住多少笔上屏，撤完就撤不到更早的了（1–1000）
  "actions/max_backspaces": 500                # 一次动作最多删多少个字符，超过的部分不删（1–10000）
  "actions/debounce_ms": 200                   # 连按保护：这么多毫秒内重复触发不执行，只对文本触发码生效（0–10000）
  "actions/key_gap_ms": 30                     # 每个按键之间（含多步动作）等多少毫秒；程序反应慢就调大（0–500）
  "actions/history_ledger": true               # 读 rime 的提交历史，把万象快符打出来的符号也补进上屏记录
  "actions/debug": false                       # 默认只写出错信息；排查问题时改 true，才会记每次动作的细节
  "actions/symbols": "，。！？；：、,.!?;:"      # 哪些字符算“符号”；写了就替换默认值
```

- `stack_size`：上屏记录的条数，超出后最早的记录被丢弃，撤不到更早的内容。
- `max_backspaces`：单次动作删除字符数的上限。
- `debounce_ms`：只对文本触发码生效，这段时间内重复触发不执行；快捷触发码不受影响。
- `key_gap_ms`：多步动作或带修饰键的动作，相邻按键之间等待的毫秒数。某些程序处理按键较慢，
  动作只执行一部分时调到 100–200。
- `history_ledger`：默认 `true`。开启后每次按键都会读一次 rime 的提交历史
  （`context.commit_history`），把新增的记录补进上屏记录。万象快符这类由脚本直接调
  `engine:commit_text()` 打出来的符号不会触发上屏通知，只能从历史里补回来，否则回删会少删一个。
  写 `false` 就不读历史（行为与旧版一致）；dll 或 rime 没有这个接口时自动失效。
- `debug`：默认 `false`，只写 `error` 级别的日志（出错才有）。要排查"按键没反应""AI 没回答"
  这类问题时改成 `true`，才会记录每次动作、每次上屏、每轮请求的细节。改完重新部署即可，不用重编。
- `symbols`：默认包含中文标点、英文标点、中文引号、书名号、各类括号，以及加号、星号、
  斜杠、竖线、`&`、`^`、`%`、`$`、`#`、`@`、`~`、反引号、间隔号、度号、正负号、乘号、除号
  等字符。`@to-symbol`、`@to-symbol-include` 和 AI 的"去掉末尾符号"都按这个集合判断。
  写法是直接把字符连在一起，不加分隔；换行写 `\n`、制表写 `\t`、反斜杠写 `\\`、
  双引号写 `\"`。

### 5. 搜索

```yaml
patch:
  "actions/search_url": "https://www.baidu.com/s?wd=%s"   # f; 搜索时用哪个引擎，%s 处换成搜索词
```

- `%s` 是搜索词的位置，提取到的文字会拼进去，中文自动做 URL 编码。
- 只接受 `http://` 或 `https://` 开头的地址，其他协议不打开。
- 其他引擎：必应 `https://www.bing.com/search?q=%s`、谷歌
  `https://www.google.com/search?q=%s`。

### 6. AI 模式

#### 用法

1. 配置 `actions/ai/enabled: true`，并给一个触发码指向 `@ai`，如 `ai;=@ai`。
2. 敲 `ai;` 进入 AI 模式，正常打字并上屏。
3. 连按两下发送键（默认 `/`），把最近一句话发给模型。
4. 回复写到光标处。
5. `Esc` 取消当前请求（取消后可以直接再发，不用等），再敲一次 `ai;` 退出模式。

#### 发送键

- 单字符发送键（默认 `/`）：第一下不拦截，正在打字时进入编码，未打字时由扩展接管；在
  `double_ms` 内按下第二下才发送，并把第一下带进编码的那个字符摘掉。
- 组合键发送键（如 `ctrl+enter`）：按一次即发送。
- 要发送的文字里没有汉字时不发送。

#### 发剪贴板里的文字

1. 敲触发码进入 AI 模式。
2. 在任意程序里选中文字，按 `Ctrl+C` 复制。
3. 按剪贴板发送键（默认 `Ctrl+Alt+;`），剪贴板内容作为发送内容。
4. 回复写到光标处。

- 只在 AI 模式下有效，其他时候这个键不动作。
- 剪贴板为空时不发送，日志记 `nothing to send (clipboard: …)`。
- 超过 `clip_max_chars` 的按字符截断，日志记 `clipboard truncated to N chars`。
- 这条路径不要求文字里有汉字，英文和代码也可以发。
- 剪贴板由后台读取，按键不会卡住输入法；5 秒内读不到就放弃，日志记 `clipboard read timed out`。
- 需要带 `clipboard_request` / `clipboard_take` 的新版 `actions.dll`（本目录这版）；旧 dll 只在启动日志里
  记 `clipboard sending disabled`，其它功能不受影响。

#### 发送的内容

- `source` 为 `auto`（默认）：输入框里有未上屏的编码时发编码内容，否则发已上屏的文字。
- 一次提问分几次上屏时，从最后一次上屏往前拼在一起，直到碰到 `sentence_marks` 里的断句符
  为止；发送的是断句符之后的内容（末尾连着的符号跳过不算）。所以分几次打完的一句话会
  完整发出去，中间的断句符则是分界。
- 上下文分两块，合计不超过 `history_chars` 个字符（它只影响带多少上下文，不影响发哪一句）：
  - 之前答过的内容按问答成对发送（一问一答两条消息，从最近的往前取）；
  - 这一段的断句点之前的文字，作为 `【上文】` 附在提示词后。

### 7. AI 拼音候选（可选，默认关闭）

开着的时候，正常打拼音，第一个候选的拼音会交给 AI，AI 给出的词作为第一个候选显示、注释是
`AI`，其它候选全部保留、顺序不变。只有你自己按数字或空格选中，它才会写上屏。

#### 接线

这一项要挂两个滤波器，位置有要求：读拼音的那个必须在 `super_comment_preedit` 之前（之后注释
已被改写，取不到拼音），插候选的那个在 `uniquifier` 之前。

```yaml
patch:
  "engine/filters/@before 5": lua_filter@*wanxiang.ziji.ai_pinyin_capture
  "engine/filters/@before 17": lua_filter@*wanxiang.ziji.ai_pinyin_insert
```

`@before N` 的 N 是下标，从 0 开始数。核对方法：打开
`<Rime 用户目录>\build\wanxiang_pro.schema.yaml`，在 `filters:` 下面从 0 数一遍，两个位置应分别
落在 `super_comment_preedit` 之前、`uniquifier` 之前。方案里的滤波器数量不同时按这个规则改 N。

两个滤波器只在用 `aiur;` 打开模式之后才工作：没打开时不写任何状态、候选原样输出，跟没有接
这两行一样。

#### 用法

1. 打 `aiur;` 打开 AI 拼音候选，再打一次关闭（只有这个触发码能开关，`Esc` 不会关掉它）。
2. 正常打拼音，候选出来后停手（默认 400 毫秒）会发一次请求。
3. 结果回来后第一个候选变成 AI 给的词，注释是 `AI`；如果 AI 挑中的就是第一位，也会在它的注释上显示 `AI`。
4. 按数字或空格选中上屏，与普通候选一样。
5. 不想等这次回答时按 `Esc`：只丢掉这次请求，模式仍然开着，接着打字就行。

模型能收到前几个候选的文字（`send_candidates`，默认 5 个），所以它可能直接从里面挑一个：
挑中的就是当前第一位时不插新候选，改为在它的注释上显示标记（默认 `AI`）；挑中后面某个候选时会把它提到第一位，列表里会看到两行
同样的词（一行带 `AI`）。这样它既能提醒你某个已存在的候选更合适，也能另造一个新词。

#### 不出 AI 候选的情况

- 第一个候选没有词库拼音：自定义短语（`b`、`jys` 这类编码）、英文、日期、数字。
- 音节数超过 `max_chars`（默认 12）。
- AI 返回的不是汉字、字数与音节数不符、或返回 `NONE`。
- 一个候选的字与音节对不上（儿化音、单字合并音节）。

按 `Ctrl+S` 可以把候选注释切成带调拼音，能直接看到某个候选有没有拼音、拼音是什么。

#### 全部配置

```yaml
patch:
  "actions/ai_pinyin/enabled": false                     # 开关；false 时触发码也不生效
  "actions/ai_pinyin/trigger": "aiur;"                   # 开关触发码（最后一个是末键）
  "actions/ai_pinyin/debounce_ms": 400                   # 停手多久才发请求（0–5000 毫秒）
  "actions/ai_pinyin/context_chars": 160                 # 附给模型的上文字数（0–5000）
  "actions/ai_pinyin/max_chars": 12                      # 最多几个音节（1–32）
  "actions/ai_pinyin/send_candidates": 5                 # 把现有前几个候选一起发给模型（0 = 只发拼音）
  "actions/ai_pinyin/marker": "AI"                       # 候选注释里的标记
  "actions/ai_pinyin/prompt": "……"                       # 提示词，不写用内置的（见下）
  "actions/ai_pinyin/retry_ms": 10000                    # 同一串拼音失败后等多久才重试（0 = 每次都重试）
```

`prompt` 不写时用这段（原文）：

```text
你是拼音输入法的补全工具。用户会给你三样东西：
1. 一串无声调拼音，音节之间用空格分开；
2. 输入法现有的前几个候选词；
3. 光标前的一小段上文（可能为空）。
请结合上文判断用户真正想打哪个词：先看看现有的候选是否合理，合理就把它原样输出；
如果候选中的词不合理时，你再按拼音另造一个。要求：
- 汉字个数必须等于拼音音节数；
- 每个字的读音必须与对应的音节一致；
- 只输出这一个词，不要标点、空格、拼音或解释；
```

接口配置与 AI 模式共用同一组键：`actions/ai/provider` 与 `actions/ai/online/*`（或 `local/*`）。
请求体格式、回复解析与 AI 模式完全相同（只读 `choices[0].message.content`）。

同一串拼音失败（网络错误、`NONE`、字数不符）之后，`retry_ms` 之内不会再问第二次；继续打字换了编码
就重新算，不受影响。

## 五、注意事项

1. 动作会向当前程序发送真实按键，效果与手动按键相同，会改动文档内容。执行前确认光标位置。
2. 管理员权限的窗口可能收不到按键：Windows 的权限隔离会拦截低权限进程发给高权限窗口的
   模拟按键。
3. `Ctrl+Shift` 组合默认被 Windows 用作"切换键盘布局"，这时 `ww;` 一类动作会切输入法。
   在"设置 → 时间和语言 → 输入 → 高级键盘设置 → 输入语言热键"里把切换布局改为"未分配"。
4. 各程序对 `Home` 的处理不同：有的先到行首非空白处，再按一次才到行首。
5. `@search` 会启动默认浏览器，地址为空或不是 `http(s)://` 时不打开。
6. AI 会把文字发往网络。仅在开启 `actions/ai/enabled` 并进入 AI 模式后才发送；密钥明文保存
   在配置文件里。回复写入当前光标处，这期间不要切换窗口。
7. 触发码与方案的快符（`x/` 之类）使用同一空间，重复时方案优先，扩展收不到。
8. 改配置后要重新部署才生效。
9. AI 拼音候选和 AI 模式共用一条请求通道：一边有请求在跑时，另一边要等它回来。
10. 候选注释里的 `AI` 只是标记，不影响候选项本身，选中照样正常上屏。
11. 手按退格会让上屏记录跟着少一个字，撤回合数、`【上文】`、AI 的删除长度都跟屏幕一致。
   `Ctrl+Backspace`、选中后删除、鼠标删、程序自己的撤销识别不了，这些之后账本会比屏幕多算。

## 六、常见问题

**敲触发码没反应**

- 确认在中文输入状态，文本触发码只在中文状态生效。
- 看日志 `mode=` 是否含 `text`；没有说明 `actions/trigger` 没读到（键名写错或没重新部署）。
- 触发码含方案 `speller/alphabet` 之外的字符时打不出来，也就无法触发。

**模块没加载**

- 看日志 `module=loaded` 还是 `MISSING`。`MISSING` 说明 `actions.dll` 不在配置目录里或改了名。
- 核对接线行 `lua_processor@*wanxiang.ziji.actions` 与实际目录是否对应。

**动作只执行一部分**

- 调大 `actions/key_gap_ms`，如 100–200（上限 500）。

**AI 没有回复**

- `ai: request failed - HTTP 401`：密钥错误。
- `HTTP 404`：`base_url` 或 `model` 错误。
- `nothing to send`：没有可发送的文字（没有上屏记录，或文字里没有汉字）。
- `previous request still running`：上一个请求未返回。

**剪贴板发送不动作**

- 启动日志里有 `clipboard sending disabled`：`actions.dll` 太旧（缺 `clipboard_request` / `clipboard_take`），换本目录这版。
- 日志 `clipboard is busy, not reading again`：上一次还没读回来，等一下再按。
- 日志 `clipboard read timed out`：5 秒内没读到，剪贴板可能被别的程序占着。

**某一项触发码/动作不生效**

- 日志 `bad key sequence disabled`：动作里有多余的分隔符（开头、结尾或连续两个），改掉这一项。
- 日志 `bad shortcut entry ignored`：这一项缺 `=`，或不是已知的内置动作。
- 日志 `duplicate trigger` / 与 `actions/trigger` 相同：只保留第一项。

## 七、全部配置项一览

下面按功能分成四块，每块都能单独整段复制。值是默认值，写与不写效果一样；注释说明这一项是干什么的。

### 1. 触发方式与快捷触发码

```yaml
patch:
  "actions/trigger": "qq/"                     # 文本触发码：打完它再按最后一个字符就撤回上一次上屏；none / off / - 关闭
  "actions/hotkey": ""                         # 另设一个组合键做同样的撤回，如 "Control+slash"；留空不启用
  "actions/shortcuts": "@defaults"             # 快捷触发码表：@defaults 用内置 26 项；也可以只写 "hh;=shift+home"；重复的只留第一项
```

### 2. 删除、记账、搜索、加载、日志

```yaml
patch:
  "actions/stack_size": 50                     # 最多记住多少笔上屏，撤完就撤不到更早的（1–1000）
  "actions/max_backspaces": 500                # 一次动作最多删多少字符（1–10000）
  "actions/debounce_ms": 200                   # 连按保护：这段时间内重复触发不执行，只对文本触发码生效（0–10000）
  "actions/key_gap_ms": 30                     # 相邻两个按键之间等多少毫秒；程序反应慢就调到 100–200（0–500）
  "actions/history_ledger": true               # 读 rime 的提交历史，把万象快符打出来的符号也补进上屏记录
  "actions/symbols": "，。！？；：、,.!?;:"      # 哪些字符算“符号”：删到符号、AI 去掉末尾符号都按它判断
```

### 4. AI 拼音候选

```yaml
patch:
  "actions/ai_pinyin/enabled": false           # 总开关；false 时 aiur; 不生效，滤波器也不改动任何东西
  "actions/ai_pinyin/trigger": "aiur;"         # 进 / 出这个模式的触发码
  "actions/ai_pinyin/debounce_ms": 400         # 停手多久才发请求（0–5000 毫秒）
  "actions/ai_pinyin/context_chars": 160       # 附给模型的上文字数（0–5000）
  "actions/ai_pinyin/max_chars": 12            # 最多几个音节，超了直接不发（1–32）
  "actions/ai_pinyin/send_candidates": 5       # 连同前几个候选一起发给模型；0 = 只发拼音
  "actions/ai_pinyin/marker": "AI"             # 候选注释里显示的标记；空串不显示
  "actions/ai_pinyin/retry_ms": 10000          # 失败后冷却多久再试这一串（0–600000，0 = 每次都重试）
  "actions/ai_pinyin/prompt": ""               # 提示词；留空或删掉这一行就用内置那条（见 三.7）
```
