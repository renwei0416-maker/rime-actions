# 上屏动作（rime-actions）使用说明

给 Rime / 小狼毫用的一个小扩展：把已经上屏（或正在输入框里）的文字**撤回、选中、复制、删除**，
还可以用 `@search` 直接拿去搜索，或者 `@ai` 交给 AI 模型处理后再写回光标处。

它不改变输入法的打字方式，只是在你敲出特定触发码时替你按几下键。

---

## 一、功能

### 1. 四种触发方式

四种方式可以同时使用，各自独立。

| 方式 | 怎么触发 | 默认 |
| --- | --- | --- |
| 文本触发码 | 中文输入状态下敲 `qq/` | 可用 |
| 组合键 | 按 `Ctrl+/` 之类 | 不启用（要配置） |
| 快捷触发码 | 敲 `z;`、`ss;`、`f;` 等 | 不启用（要配置） |
| AI 模式 | 敲 `ai;` 进入，打字后连按两下 `/` | 不启用（要配置） |

### 2. 能做什么

| 动作 | 效果 |
| --- | --- |
| 撤回上屏 | 把最近一次上屏的文字删掉；连按可以一笔一笔往前撤（按上屏顺序倒着撤） |
| 组合键撤回 | 同上，但用组合键触发，不占用触发码 |
| 按键动作 | 向当前程序发送任意按键/组合键，如 `ctrl+z`、`shift+home`、`ctrl+shift+left` |
| 多步动作 | 用 `-` 或 `,` 连接多个动作，依次执行，如 `shift+home-ctrl+c` |
| 删到符号 | 从光标往前删到第一个符号为止，可保留或连同符号一起删 |
| 删最近一笔 | 只删最近一次上屏的文字 |
| 搜索 | 用默认浏览器搜索最后一次上屏的文字 |
| AI | 把文字发给 OpenAI 格式的接口，把回复直接写到光标处 |

## 二、安装

### 1. 放文件

到 Releases 下载 x64 包（`rime-actions-<版本>-x64.zip`），解压后得到两个文件，
放进 Rime 的用户目录（小狼毫一般是 `%APPDATA%\Rime`，即
`C:\Users\<你的用户名>\AppData\Roaming\Rime`）：

```
<Rime 用户目录>\lua\wanxiang\ziji\actions.lua
<Rime 用户目录>\lua\wanxiang\ziji\actions.dll
```

两个文件必须在同一个目录里，`actions.dll` 的名字不能改。

### 2. 接线

在你的方案配置文件里挂上处理器。如果用的是 `wanxiang_pro` 方案，就改
`<Rime 用户目录>\wanxiang_pro.custom.yaml`；别的方案就改对应名字的 `*.custom.yaml`。

```yaml
patch:
  "engine/processors/@before 0": lua_processor@*wanxiang.ziji.actions
```

- `@before 0` 表示排在处理器链最前面；这样按键会先经过本扩展，不会被别的组件先吃掉。
- `*wanxiang.ziji.actions` 对应 `<Rime 用户目录>\lua\wanxiang\ziji\actions.lua`。
  文件换到别的目录时，这一段要跟着改。

### 3. 重新部署

保存后让小狼毫重新部署（右键托盘图标 → 重新部署）。之后在任意能打字的地方敲 `qq/`
试试：最近一次上屏的文字应该被删掉。

## 三、配置

所有配置都写在 `*.custom.yaml` 的 `patch:` 下面，键名以 `actions/` 开头。
**改完要重新部署**。全部都是可选的，不写就是默认值。

### 1. 文本触发码

```yaml
patch:
  "actions/trigger": "qq/"
```

- 至少 2 个字符，字符必须在方案的 `speller/alphabet` 里。
- 只有"已经打出的编码恰好等于前缀、并且这一次按的是最后一个字符"时才触发。
  `qq/` 就是先打出 `qq`，再按 `/`。
- 写成 `none`、`off` 或 `-` 表示关掉这种方式。
- 触发的一瞬间，最后一个字符会被这个扩展吃掉，不会上屏。

### 2. 组合键

```yaml
patch:
  "actions/hotkey": "Control+slash"
```

- 格式是 `修饰键+键名`，修饰键可以写 `Control`/`Ctrl`、`Alt`、`Shift`、`Super`，
  可以叠多个，如 `Control+Shift+slash`。
- 键名用 Rime 的键名：`slash`、`space`、`return`、`escape`、`backspace`、`left`、
  `right`、`up`、`down`、`home`、`end`、`pageup`、`pagedown`、`delete`、`tab` 等。
- 留空（默认）= 不启用。
- 和文本触发码可以同时用：先看组合键，没命中再按文本触发码判断。
- 输入框里有没打完的编码时，组合键不动作。

### 3. 快捷触发码

```yaml
patch:
  "actions/shortcuts": "@defaults"
```

- 默认**一个都不启用**；写了这一行才启用脚本内置的表。
- 多项之间用空格隔开，每一项是 `触发码=动作`。
- 不写 `@defaults` 就表示"只有你写的这几项"；写上 `@defaults` 再跟几项表示混写。
- 触发码同样至少 2 个字符，最后一位是单独的按键；`z;` 就是先打 `z` 再按 `;`。
- 重复的触发码只保留第一项，后面的忽略并记一条错误日志。

#### 内置默认表（26 项）

| 触发码 | 动作 | 触发码 | 动作 |
| --- | --- | --- | --- |
| `z;` | `ctrl+z` 撤销 | `y;` | `ctrl+y` 重做 |
| `a;` | `ctrl+a` 全选 | `c;` | `ctrl+c` 复制 |
| `v;` | `ctrl+v` 粘贴 | `xx;` | `ctrl+x` 剪切 |
| `s;` | `up` 上移一行 | `x;` | `down` 下移一行 |
| `g;` | `end` 行尾 | `t;` | `home` 行首 |
| `w;` | `ctrl+shift+left` 选中前一个词 | `b;` | `ctrl+backspace` 删前一个词 |
| `r;` | `ctrl+delete` 删后一个词 | `h;` | `ctrl+home` 到文首 |
| `e;` | `ctrl+end` 到文末 | `d;` | `delete` 删除 |
| `kk;` | `ctrl+shift+k` 删整行 | `aa;` | `ctrl+a-ctrl+c` 复制全文 |
| `dd;` | `ctrl+shift+backspace` 删整行 | `ww;` | `ctrl+shift+left-ctrl+c` 复制前一个词 |
| `hh;` | `shift+home-ctrl+c` 复制整行 | `tt;` | `ctrl+shift+home-ctrl+c` 复制光标之上全部 |
| `gg;` | `ctrl+shift+end-ctrl+c` 复制光标之下全部 | `ss;` | `shift+home` 选中到行首 |
| `ff;` | `@to-symbol` 删到前一个符号 | `f;` | `@search` 搜索最后一次上屏 |

#### 动作的三种写法

1. **按键/组合键**：直接写 Rime 键名，如 `ctrl+z`、`shift+home`、`ctrl+backspace`。
   常用键名：字母 `a`–`z`、数字 `0`–`9`、`f1`–`f12`、`numpad0`–`numpad9`、
   `left`/`right`/`up`/`down`、`home`/`end`/`pageup`/`pagedown`、`insert`/`delete`、
   `backspace`/`tab`/`return`/`space`/`escape`、`slash`/`backslash`/`semicolon` 等。
2. **多步动作**：`shift+home-ctrl+c`，也可以用逗号 `shift+home,ctrl+c`，两种等价。
   每一步都是"修饰键按下 → 按键按下 → 按键抬起 → 修饰键抬起"。
3. **内置动作**（以 `@` 开头）：

| 写法 | 作用 |
| --- | --- |
| `@to-symbol` | 从光标往前删到第一个符号，符号保留 |
| `@to-symbol-include` | 同上，但符号一起删掉 |
| `@delete` | 删掉最近一次上屏的文字 |
| `@search` | 用默认浏览器搜索最后一次上屏的文字 |
| `@ai` / `@ai:<名字>` | 进入 AI 模式，用 `actions/ai/prompts/<名字>` 的提示词 |

例子：

```yaml
patch:
  # 只要这几项
  "actions/shortcuts": "z;=ctrl+z  y;=ctrl+y  ss;=shift+home  ff;=@to-symbol  f;=@search"

  # 内置 26 项 + 自己加两项
  "actions/shortcuts": "@defaults eq;=ctrl+end  wq;=ctrl+shift+right"
```

#### 选中类动作

`ss;`（`shift+home`）只把光标移到行首并选中，不会复制。要"复制整行"用
`hh;`（选到行首 + `ctrl+c`）。要连行尾的换行一起选中，再加一步 `shift+left`：

```yaml
  "actions/shortcuts": "@defaults sq;=shift+home,shift+left"
```

### 4. 符号集

`@to-symbol` / `@to-symbol-include` 和 AI 的"去掉末尾符号"都按这个集合判断。

```yaml
patch:
  "actions/symbols": "，。！？；：、,.!?;:…—～「」『』【】《》（）()[]{}<>+*/|&^%$#@~`·"
```

- 直接写字符，不要加空格分隔。
- 换行写 `\n`、制表写 `\t`、反斜杠写 `\\`、双引号写 `\"`。
- 放进去的字符都算"符号"。

### 5. 删除上限与连按保护

```yaml
patch:
  "actions/stack_size": 50        # 最多能往前撤多少笔
  "actions/max_backspaces": 500   # 单次最多删多少字符
  "actions/debounce_ms": 200      # 连按保护（毫秒）
```

- `stack_size`：记录了多少次上屏。超出后最早的记录被丢掉，也就撤不到那么前面。
- `max_backspaces`：一次动作最多删多少字符，防止误删太多。上限 10000。
- `debounce_ms`：只对文本触发码生效。触发后这段时间内再敲触发码不会重复执行。
  快捷触发码不受它影响。

### 6. 按键间隔

```yaml
patch:
  "actions/key_gap_ms": 30
```

- 多步动作或带修饰键的动作，相邻两个按键之间等待的毫秒数，默认 30，范围 0–500。
- 有的程序处理按键慢，动作会"只走一半"，这时把它调大（如 100～200）。

### 7. 搜索

```yaml
patch:
  "actions/search_url": "https://www.baidu.com/s?wd=%s"
```

- `%s` 处会替换成搜到的文字，中文会自动做 URL 编码。
- 必须以 `http://` 或 `https://` 开头，其他协议会被拒绝。
- 也可以用必应 `https://www.bing.com/search?q=%s`、谷歌 `https://www.google.com/search?q=%s` 等。

### 8. AI 模式

#### 怎么用

1. 给一个触发码指向 `@ai`，例如 `ai;=@ai`（译英用 `@ai:eng`，译日用 `@ai:jp`）。
2. 敲 `ai;` 进入 AI 模式。之后正常打中文，上屏。
3. 连按两下发送键（默认 `/`），把最近一句话发给模型。
4. 回复会直接打到光标处。
5. `Esc` 只取消这一次；再敲一次 `ai;` 退出 AI 模式。

发送键的行为：

- 第一下 `/` 不拦：正在打字时会进到编码里（不影响方案里 `x/` 这类快符），
  没在打字时才由本扩展接管。
- 第二下在 `double_ms` 内按下才算"连按两下"，这时会把第一下带进编码的那个字符摘掉再发送。
- 组合键形态（如 `ctrl+enter`）按一次就发送。
- 要发送的文字里没有汉字时不发送。

#### 发送什么

- 默认（`source: "auto"`）：输入框里还有没上屏的编码就发输入框里的文字，否则发已上屏的文字。
- 只发**最后一句话**：从末尾往前找 `sentence_marks` 里的断句符号，取它后面那一段；
  末尾连着的符号不算，会一起跳过去。
- 还会带上前文（`history_chars` 个字符）作为上下文。

#### 配置

```yaml
patch:
  "actions/ai/enabled": true
  "actions/ai/online/api_key": "sk-……"          # 换成你的密钥
  "actions/shortcuts": "@defaults ai;=@ai eng;=@ai:eng jp;=@ai:jp"
```

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `actions/ai/enabled` | `false` | 总开关；不开时 `@ai` 触发码不生效 |
| `actions/ai/send_key` | `"/"` | 发送键；写一个字符=连按两下，写组合键（如 `ctrl+enter`）=按一次 |
| `actions/ai/double_ms` | `1000` | "连按两下"的时间窗口（毫秒），最大 5000 |
| `actions/ai/source` | `"auto"` | `auto` / `composition`（发输入框）/ `committed`（发已上屏） |
| `actions/ai/sentence_marks` | `"。！？"` | 断句符号集合 |
| `actions/ai/include_marks` | `false` | 断句符号是否一起发给模型 |
| `actions/ai/replace` | `false` | 为 `true` 时先把原句删掉再写入回复（只删同一行内的内容） |
| `actions/ai/skip_ai_output` | `true` | 再次触发时跳过上一次 AI 写入的文字 |
| `actions/ai/history_chars` | `200` | 作为上下文带上的前文字数，0 = 不带 |
| `actions/ai/nudge` | `true` | 回复到达后用空键把输入法叫醒（否则要等下一次按键才写出来） |
| `actions/ai/nudge_key` | `135` | 叫醒用的虚拟键码，135 = F24（一般不用改） |
| `actions/ai/nudge_interval_ms` | `350` | 叫醒的间隔（毫秒） |
| `actions/ai/max_wait_s` | `60` | 等回复的最长秒数，超时自动取消 |
| `actions/ai/provider` | `"online"` | `online` 用云接口；`local` 用本地接口 |
| `actions/ai/online/base_url` | `https://api.deepseek.com/chat/completions` | 接口地址 |
| `actions/ai/online/model` | `deepseek-chat` | 模型名 |
| `actions/ai/online/api_key` | 空 | 密钥，明文保存 |
| `actions/ai/online/thinking_disabled` | `false` | 请求里是否加 `"thinking":{"type":"disabled"}` |
| `actions/ai/online/max_tokens` | `1024` | 回复长度上限 |
| `actions/ai/online/temperature` | `0.7` | 随机度，0–2 |
| `actions/ai/local/*` | 同上（默认 `http://127.0.0.1:11434/v1/chat/completions`、`qwen2.5:7b`） | 本地接口的六项同名配置 |
| `actions/ai/prompts/<名字>` | 见下 | 提示词 |

接口按 OpenAI 的 `chat/completions` 格式：请求是 JSON，回复只读
`choices[0].message.content`。

#### 提示词

脚本内置三份：`default`（通用）、`eng`（译成英文）、`jp`（译成日文）。
要自定义就写同名键，覆盖内置的：

```yaml
patch:
  "actions/ai/prompts/polish": >
    你是中文润色助手。把用户给的一句话改写得更通顺，只输出改写后的句子，不要解释。
  "actions/shortcuts": "@defaults p;=@ai:polish"
```

`@ai` 不带名字时用 `default`。AI 模式下直接敲别的 `@ai` 触发码可以换提示词，不用先退出。

## 四、日志

```
actions.lua: mode=text+shortcut+ai trigger=qq/ hotkey=- shortcuts=26 ...
actions.lua: ai: request sent (seq=1)
actions.lua: ai: inserted 5 chars
actions.lua: ai: request failed - HTTP 401
actions.lua: nothing to delete
```

`mode=` 后面列出当前生效的几种触发方式，都没生效是 `off`；`module=` 是 `loaded` 或 `MISSING`。

## 五、注意事项

1. **会真的按键**。所有动作都是向当前程序发送真实按键/组合键，和手动按一样，也会改动
   文档内容。用之前先确认光标位置。
2. **管理员权限的窗口可能收不到**。Windows 的权限隔离（UIPI）会挡住低权限进程发给
   高权限窗口的模拟按键。
3. **`Ctrl+Shift` 组合可能被系统抢走**。Windows 默认把 `Ctrl+Shift` 当作"切换键盘布局"，
   这时 `ww;` 之类的动作会变成切输入法。需要在"设置 → 时间和语言 → 输入 →
   高级键盘设置 → 输入语言热键"里把切换布局改成"未分配"。
4. **不同程序的 `Home` 不一样**。有的编辑器按 `Home` 是先到行首非空白处，再按一次才是行首，
   这类动作在各程序里效果会略有差别。
5. **`@search` 会拉起浏览器**。只接受 `http(s)://` 地址；地址是空或者非法时不会打开。
6. **AI 会把文字发到网上**。只有开了 `actions/ai/enabled` 并敲了 `@ai` 触发码才会发；
   密钥明文保存在配置文件里，注意别把配置文件发给别人。回复直接写进当前光标处，
   这期间不要切换窗口。
7. **触发码要避开方案里已有的码**。触发码是"编码 + 一个字符"的形式，和方案的快符
   （`x/` 之类）同属一个空间，重复时以方案的为准，本扩展收不到。
8. **改配置要重新部署**，否则改动不生效。

## 六、常见问题

**敲了触发码没反应**

- 先看是不是在中文输入状态：文本触发码只在中文状态下起作用。
- 看日志里 `mode=` 有没有 `text`；没有就是 `actions/trigger` 没读到（键名写错、没重新部署）。
- 触发码写在方案的 `speller/alphabet` 外时打不出来，那就永远触发不了。

**模块没加载**

- 看日志里 `module=loaded` 还是 `MISSING`。`MISSING` 说明 `actions.dll` 不在配置的目录里，
  或者改名了。
- 检查接线那一行的路径：`lua_processor@*wanxiang.ziji.actions` 要和实际目录对应。

**动作只走了一半**

- 把 `actions/key_gap_ms` 调大，如 100～200（最大 500）。

**AI 没有回复**

- `ai: request failed - HTTP 401`：密钥不对。
- `HTTP 404`：`base_url` 或 `model` 写错。
- `nothing to send`：没有可发送的文字（没上屏、或者文字里没有汉字）。
- `previous request still running`：上一个请求还没回来，等一下再按。
